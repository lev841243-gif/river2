## 2. Грабли этапа — читать перед правками

### 1. Локальный поллер и боевой вебхук — взаимоисключающи
Бот на боевом принимает апдейты вебхуком. Локальная отладка
(`scripts/client-bot-dev.ts`) — через `getUpdates` (polling). **Одновременно на
одном боте нельзя**: Telegram отдаёт 409. Значит для локальной отладки надо снять
боевой вебхук (`deleteWebhook`), а после — вернуть (`setWebhook`). Пока бот на
проде — не запускать поллер.

### 2. webp-обложки лодок Telegram принимает как есть
`sendPhoto` показывает webp-обложки нормально — проверено экспериментом (фаза 0),
конвертация не нужна. Не «на всякий случай» гнать через sharp. Запасной путь
webp→jpg — только если конкретный клиент покажет криво.

### 3. `CLIENT_BOT_DEV_MANAGER_CHAT` — только локально
Если задана, тестовая карточка заявки уходит в этот личный чат, а не в реальную
группу менеджера. **На боевом переменной быть не должно** — иначе заявки клиентов
пойдут не туда. На сервере её нет (проверено).

### 4. Скрытие лодок в боте — не через `isVisible`
`isVisible` общий с сайтом, убрал бы лодку отовсюду. Для «спрятать только в боте»
— список слагов `BOT_HIDDEN_SLUGS` в `lib/client-bot/config.ts`.
