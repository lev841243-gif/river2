## 1. Что сделано в этом этапе

### Счётчик Яндекс.Метрики + маскирование полей (`6d6010e`)
Счётчик **№111074489** заказчик прислал сам (webvisor, clickmap, ecommerce,
accurateTrackBounce, trackLinks — init-опции оставлены ровно как выдал Яндекс).

- `components/nevsky/yandex-metrika.tsx` — клиентский компонент, подключён в
  `app/layout.tsx` в начале `<body>`. Код Яндекса через **`next/script`
  (afterInteractive)**, не сырой `<script>`.
- **Грузится ТОЛЬКО в проде** (`process.env.NODE_ENV === 'production'`), как
  Vercel Analytics в `cookie-consent.tsx` — иначе localhost засорял бы статистику.
  В dev `window.ym` нет вообще, это нормально.
- **`/admin` исключён** (`pathname.startsWith('/admin')`): там ПДн клиентов,
  webvisor не должен их писать. Тот же принцип, что у баннера cookie.
- SPA-хиты: `next/script` шлёт только первый просмотр, поэтому на смену `pathname`
  шлём `ym('hit', url)` вручную.
- ⚠️ **Решения заказчика (осознанные):** Метрика работает **ВСЕГДА, не за
  согласием cookie** (в отличие от Vercel Analytics); `/privacy` **не трогали** —
  Яндекс.Метрика и передача данных в Яндекс там прямо не названы, аналитика
  описана обобщённо. Формально баннер/`/privacy` говорят «с согласия», а Метрика
  всегда-вкл — это на усмотрение заказчика, он в курсе.
- **Маскирование:** webvisor пишет содержимое полей форм. В форме брони
  (`booking-modal.tsx`) на 4 поля с ПДн — имя, телефон, Telegram, комментарий —
  добавлен класс **`ym-disable-keys`** (значения → звёздочки, записи сеансов и
  карта кликов сохраняются). Проверено по докам Яндекса. Поля e-mail в форме нет.
  `/check` — только скрытое поле с номером, не ПДн, не маскировали.

### Цели Метрики через единый helper (`4bb484d`)
`lib/metrika.ts` — `reachGoal(goal)` с проверкой `window.ym` (no-op на SSR и до
загрузки счётчика), тип `MetrikaGoal` фиксирует 6 идентификаторов (опечатка не
соберётся). Идентификаторы **заведены заказчиком в интерфейсе Метрики**.

- **`booking_click`** — в `openBooking` (`booking-context.tsx`) до `setOpen(true)`.
  Покрывает все кнопки, открывающие форму («Забронировать» = `fleet.book`,
  «Забронировать катер» = `cta.primary`, «Забронировать этот катер» =
  `fleet.bookThis`). Кнопки `nav.cta`/`hero.primary` = «Выбрать катер» — это якорь
  на `#fleet`, форму не открывают, цель не шлют.
- **`booking_open`** — mount-эффект в `BookingModal` с **реф-страховкой**
  (`openedRef`): React StrictMode в dev прогоняет эффект дважды — без страховки
  цель дублировалась. В проде страховка тоже уместна (одна цель на открытие).
- **`booking_submit`** — в ветке `if (res.ok)` перед `setStep('success')`. Только
  при реальном успехе; после — форма уходит на экран «успех», повтор невозможен.
- **`phone_click` / `telegram_click` / `whatsapp_click`** — ОДИН делегированный
  обработчик клика на `document` в `yandex-metrika.tsx`, смотрит `href` ближайшей
  `closest('a')`: `tel:` / `wa.me` / `t.me` (не пересекаются). Покрывает все
  контактные ссылки (шапка, футер, CTA, экспедиции, соц-ряд, экран успеха) без
  правок в каждом компоненте. Гейт `enabled` (прод, не /admin).
- Проверено на **боевом** (обёрткой над `ym`): `booking_click`→`booking_open`
  идут по одному разу; контактные клики классифицируются верно, в т.ч. клик по
  иконке ВНУТРИ ссылки.

### Диагностика «window.ym === undefined» — это НЕ баг
Заказчик сообщил, что на проде `typeof window.ym` = `undefined`. Проверено на
живом сайте (чистый браузер): `window.ym` = **function**, `tag.js` грузится, хиты
и цели уходят, вебвизор активен. Правок в код НЕ вносил. Причины у заказчика по
убыванию вероятности: **блокировщик рекламы/трекеров** (uBlock/AdGuard/Kaspersky
режут `mc.yandex.ru`, многие обнуляют `window.ym`); проверка **на `/admin`** (там
отключён намеренно); слишком раннее чтение (afterInteractive определяет `ym` после
гидратации). Ключ к диагнозу: noscript-пиксель в HTML есть → компонент
рендерится; если бы инлайн-скрипт не выполнялся, `ym` не появился бы вовсе.

## 2. Грабли этапа — читать перед правками

1. **`next/script` afterInteractive НЕ кладёт инлайн-скрипт в SSR-HTML** — он
   инжектится на клиенте после гидратации. В curl исходного HTML его нет, это
   норма; noscript-пиксель — есть.
2. **В Next `openGraph` страницы ЗАМЕНЯЕТ родительский целиком, не мёржит.** Задал
   на `app/page.tsx` только `openGraph:{url}` — затёрло `og:image` из layout.
   Поэтому `OG_IMAGES` подставляется в `openGraph` КАЖДОЙ страницы, а не только в
   layout. `alternates` (canonical/hreflang) — отдельное поле, мёржится нормально.
3. **`next-env.d.ts` авто-управляется Next и «прыгает»** между `import
   "./.next/types/routes.d.ts"` (локальная сборка) и `.next-build/...` (серверная
   сборка в отдельную папку из `deploy.sh`). В git он указывает на **`.next-build`**
   — так надо для сервера. **Локальный флип на `.next` НЕ коммитить.**
4. **Битые сгенерированные типы в `.next`** дали сборочную ошибку `Type error:
   Declaration or statement expected` в `AppRouteHandlerRoutes` — при чистом
   `tsc --noEmit`. Лечение: **`rm -rf .next .next-build && npm run build`**.
   Ошибка была не в исходниках.
5. **HTML-файл подтверждения прав — ТОЛЬКО в `public/`.** В корне проекта Next
   его не отдаёт (404). Тот же класс, что и с загрузками галереи в stage3.
6. **Цель `booking_open` дублировалась** из-за React StrictMode (dev гоняет
   эффекты дважды). Реф-страховка `openedRef` — не «лишний код», не убирать.
7. **Метрика прод-only** → цели тестируются ТОЛЬКО на боевом, через
   `?_ym_debug=1` (или `localStorage._ym_debug=1`) — в консоли `Reached goal: …`.
   Локально `reachGoal` no-op (нет `window.ym`); для проверки в dev подставлял
   заглушку `window.ym`.
8. **Реальный `aggregateRating` в LocalBusiness:** Яндекс его использует, **Google**
   к «самоописанному» рейтингу относится осторожно (может показать звёзды, может
   проигнорировать — без штрафа). Убрать — одна строка в `business-jsonld.tsx`.
