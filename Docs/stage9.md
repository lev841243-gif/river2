### 1.1. Кампания смотрит в ЧУЖОЙ счётчик Метрики — главное

На слайде 9 в настройках кампании видно поле «Счётчики Яндекс Метрики»:

Следствия:

## 2. Что сделано в коде

### Страницы катеров `/boat/[slug]` (`4401d5c`)

16 лодок × RU/EN = **32 страницы**, пререндер на сборке, ISR 300 с.

- **`lib/boat-seo.ts`** — пути (`boatPath`), цена (`boatPrice`), микрокопия
  (`boatCopy`) и сборщик метаданных (`buildBoatMetadata`). В отличие от
  `landings.ts` копирайт здесь **шаблонный**, а не написанный руками: страниц 16
  и они генерируются из данных лодки в БД. Добавили лодку в админке — страница
  появилась сама.
- **`components/nevsky/boat-page.tsx`** — серверный каркас: хлебные крошки, H1,
  цена, галерея, описание, ТТХ, удобства, услуги, блок «другие катера»,
  `Testimonials` + `Cta` + футер. JSON-LD: **Product + Offer** (цена за час,
  `unitCode: HUR`) и **BreadcrumbList**.
- **`components/nevsky/boat-gallery.tsx`** — клиентская галерея с миниатюрами.
  От модалки во `fleet.tsx` отличается тем, что **не вешает глобальный
  обработчик клавиш**: на странице стрелки должны прокручивать её, а не листать
  фото.
- Флот целиком на страницу катера НЕ вставляем (в отличие от лендингов) — вместо
  этого ссылки на три другие лодки. Иначе на каждой из 32 страниц висело бы по
  16 карточек с модалкой.
- `BookButton` получил `boatId` — форма брони открывается **с уже выбранным**
  катером.
- `SiteNav` получил `ruHref`/`enHref`: переключатель языка на странице катера
  вёл на `/en` вместо EN-версии этой же лодки, расходясь с hreflang. По
  умолчанию поведение прежнее — главная и лендинги не затронуты.

### 301 со старых адресов (`4401d5c`, `next.config.mjs`)

## 3. Грабли этапа — читать перед правками

1. **Цифрам аудита нельзя верить на слово.** Аудит на слайде 3 признаёт, что
   коллтрекинга нет и звонки не считаны, а на слайде 6 подаёт «2 заявки» и
   «CPL 33 000 ₽» как факт. Сверять с БД (`Booking` + UTM) и логами nginx —
   у нас данные точнее, чем у кабинета.
2. **`next-env.d.ts` снова «прыгнул»** на `.next` после локальной сборки. В git
   должен оставаться `.next-build`. Перед коммитом: `git checkout -- next-env.d.ts`.
   Грабля из stage7, наступили опять.
3. **В Next `permanent: true` отдаёт 308, а не 301.** Для переезда страниц ставим
   явный `statusCode: 301` — его понимают все краулеры без исключений. Оба поля
   одновременно указывать нельзя.
4. **Логи nginx живут две недели** (ротация, `access.log.14.gz`). Всё, что
   считаем по логам, — это окно в 14 дней, не 90. Нужна история глубже — снимать
   заранее.
5. **Прежний сайт уже не восстановить.** `45.130.41.20` по старым путям отдаёт
   404, а с правильным `Host` — 301 на новый домен. Wayback ответил 429.
   Поэтому маппинг старых слагов проверяем по логам и здравому смыслу.
6. **PDF аудита — вектор без текстового слоя** (текст в кривых). `pypdf`
   извлекает пустоту. Читается только рендером: `pymupdf` → PNG постранично →
   смотреть картинками. `pdftoppm` в системе нет.
7. **Якоря `#routes`, `#gallery`, `#reviews` в меню ведут в никуда** — у этих
   секций нет `id` (есть только `#top`, `#experiences`, `#fleet`, `#cta`,
   `#faq`, `#footer`). Давняя недоработка, не из правок этого окна. Поэтому
   `/galereya` редиректим на `/`, а не на якорь.
8. **OG-картинка страниц катеров — общий `/og.jpg` намеренно.** Обложки лодок в
   webp, а превью ссылки в Telegram/VK на webp разворачивается не везде. Тот же
   компромисс, что и у лендингов.
9. **`lib/boat-seo.ts` импортируется в клиентский `fleet.tsx`** — это нормально:
   оттуда берётся только чистая функция `boatPath`, серверного кода в модуле нет.

- **Деплой (я сам, только с одобрения заказчика):**
  ```bash
  git push origin main
  ssh -i ~/.ssh/claude-deploy-river2 root@85.198.68.244 'bash /root/dno/scripts/deploy.sh'
  ```
  Миграций в этом окне не было — только код и контент.
- **Чтение боевой БД (только SELECT):**
  ```bash
  ssh -i ~/.ssh/claude-deploy-river2 root@85.198.68.244 \
    'cd /root/dno && DB=$(grep -E "^DATABASE_URL=" .env | cut -d= -f2- | tr -d "\""); psql "$DB" -P pager=off -c "..."'
  ```
- **Анализ логов nginx** (склеить ротацию):
  ```bash
  (zcat -f access.log.*.gz; cat access.log.1 access.log) > /tmp/all
  ```

  запись в sitemap и ссылки во флоте генерируются из `getBoats()`. Руками —

- **Добавить лендинг:** объект в `lib/landings.ts` (RU+EN) → в массив `landings`
  → два тонких `page.tsx`. Порядок из stage8 не изменился.

  старых адресов, `grep -c "<url>"` в `/sitemap.xml`, `"@type":"Product"` в HTML,
